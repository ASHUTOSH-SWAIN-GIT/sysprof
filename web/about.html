sysprof

Dashboard About

sysprof measures how long Linux system calls take, using eBPF, without modifying the kernel or the programs it observes.

An OS course project. One Go binary: a terminal view, this web UI, and a recorder.

The problem

Programs spend a lot of time inside the kernel (read, write, fsync, futex, ...). When something is slow, you want to know which syscall, which process, and how bad the tail is. Tools like strace can slow a program 10x to 100x, which distorts the very latency you want to measure. eBPF observes inside the kernel with very low overhead.

How it works

  1. On sys_enter, an eBPF program stores a timestamp for the thread.
  2. On sys_exit, it computes now - start and updates a per (process, syscall) log2 histogram plus count, total and max.
  3. Aggregation happens in the kernel, so only small summaries reach user space.
  4. The Go collector reads the maps every second, keeps a 5 minute history, and estimates p50 / p95 / p99 from the histogram.
  5. The terminal view and this page both read the same data.

Features

Per syscall latencyCount, calls/s, total, average, p50, p95, p99 and max for every syscall.
Latency histogramLog2 buckets for the selected syscall, so you see the shape and the long tail, not just an average.
Percentiles over timep50 / p95 / p99 line chart from the rolling history, to spot when latency changed.
Per process breakdownWhich processes make the most calls and spend the most time, and their top syscall.
Waiting vs slowBlocking syscalls such as futex and epoll_wait are tagged wait, since long latency is expected for them.
Live updatesServer-Sent Events push a new snapshot every interval. No polling.
Filters--pid, --comm, --syscall on the CLI filter before aggregating. The filter box here hides rows.
Active syscall shieldBPF LSM denies exec, open and ptrace for matching processes before they happen. Rules change at runtime.
TCP/IP stack bypasssockmap and sk_msg move loopback TCP data straight into the peer socket. A benchmark compares both paths.
CPU scheduling policyPriority policy for CPU hogs with a live wake-up jitter probe. Uses nice values, not sched_ext.
Record modesysprof record saves one JSON snapshot per interval for later analysis.

Using it

sysprof top                      live terminal table
sysprof serve                    this web UI, on 127.0.0.1:8080
sysprof record -o out.jsonl      save snapshots to a file

Good to know

  • Each active panel shows a mode: kernel (real), simulated (--fake), or unavailable with the reason.
  • Percentiles are estimated from log2 buckets, so they are accurate to within one power of two.
  • Needs Linux with eBPF and root. On other systems it runs with generated demo data (--fake).
  • The server binds to 127.0.0.1 because the tool runs as root and exposes system internals.
  • Raw per call events are never streamed, so there is no per call outlier list. Max latency is shown instead.

Stack

eBPF programs in C (tracepoints, LSM, sockops, sk_msg), Go with cilium/ebpf for the collector, store and HTTP server, cobra for the CLI, and a single embedded HTML page with canvas charts.
