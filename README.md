# sysprof

Measures how long Linux system calls take, using eBPF. One Go binary: a terminal
`top` view, a web UI, and a recorder. No kernel changes and no changes to the
observed programs.

## How it works

- Two tracepoints, `raw_syscalls:sys_enter` and `sys_exit`, in `bpf/syscall_latency.c`.
- Enter stores a timestamp keyed by thread id. Exit computes the latency and
  updates a per (pid, syscall) log2 histogram plus count, total and max.
- Go reads the map every `--interval` (default 1s), keeps the last 300 intervals,
  and estimates p50/p95/p99 from the histogram buckets (approximate).
- Calls are grouped into categories (file, memory, network, process, sync,
  signal, time) for a workload summary.
- Each interval is compared with the recent median p95, and a syscall is tagged
  as a spike when it is at least 2x slower (and 25us above the baseline).
- Blocking syscalls (`futex`, `epoll_wait`, `nanosleep`, ...) are tagged `wait`
  because long latency is expected for them.

```
bpf/ (C) -> eBPF maps -> internal/collector -> internal/store -> CLI top/record
                                                             \-> internal/server (REST, SSE) -> web/
```

## Run

Full instructions for Linux and non-Linux machines: [USAGE.md](USAGE.md).

Needs Linux 5.x+ with BTF (`/sys/kernel/btf/vmlinux`), tracefs mounted, and root.

```
make build
sudo bin/sysprof top
sudo bin/sysprof serve --addr 127.0.0.1:8080
sudo bin/sysprof record -o out.jsonl
bin/sysprof export -i out.jsonl --what categories -o categories.csv
```

Flags: `--pid`, `--comm`, `--syscall`, `--interval`. `export` takes
`--what syscalls|processes|categories`, `-i` and `-o` (`-` is stdout).

On a Mac there is no eBPF. Use demo data to work on the UI and CLI:

```
make demo            # or: bin/sysprof top --fake
```

To run for real, cross compile and run inside a Linux VM (Lima, OrbStack, UTM):

```
make build-linux     # GOARCH=amd64 on Intel
```

## Active controls

Beyond measuring, the dashboard can change kernel behaviour. Each panel shows
a mode badge: `kernel` (real), `simulated` (`--fake`), or `unavailable` (with
the reason, the other panels keep working).

- **Syscall shield** (`bpf/shield_lsm.c`): BPF LSM hooks deny `exec`, `open`
  and `ptrace` for processes matching rules, with `EPERM` or `SIGKILL`. Rules
  are pushed into a kernel map at runtime. "Simulate attack" runs a harmless
  attacker process against demo rules.
- **TCP/IP bypass** (`bpf/sock_bypass.c`): sockops registers loopback sockets
  in a sockhash and an sk_msg program redirects each send straight into the
  peer's receive queue. "Run benchmark" compares a 100k round trip ping-pong
  with the bypass off and on.
- **CPU scheduling policy** (`internal/scheduler`): Stress workers burn CPU,
  the policy sets their nice value, and a probe measures wake-up jitter. This
  does not load a `sched_ext` scheduler (needs `CONFIG_SCHED_CLASS_EXT`).

These need root and, for the shield, `bpf` in `/sys/kernel/security/lsm`.
State changing endpoints require the `X-Sysprof-Action: 1` header, a same
origin request and a loopback listen address. Shield rules and the sockmap
programs disappear when the process exits.

## API

- `GET /api/snapshot`: per syscall stats (cumulative, plus current calls/s),
  categories and interval spikes
- `GET /api/history`: per interval p50/p95/p99 and rate
- `GET /api/processes`: per process stats
- `GET /api/export.csv?what=syscalls|processes|categories`: CSV of the latest snapshot
- `GET /stream`: SSE, one `{snapshot, history, active}` event per interval
- `GET /api/shield`, `POST /api/shield/rules`, `DELETE /api/shield/rules/{id}`, `POST /api/shield/simulate`
- `GET /api/bypass`, `POST /api/bypass/toggle`, `POST /api/bypass/benchmark`
- `GET /api/scheduler`, `POST /api/scheduler/policy`, `POST /api/scheduler/stress`

The server binds to `127.0.0.1` by default because the tool runs as root and
exposes system internals.

## Development notes

- The `*_bpfel.*` files in `internal/collector`, `internal/shield` and
  `internal/sockbypass` are generated and committed so Linux builds do not need
  clang. Regenerate with `make generate` after editing a C file.
- `internal/syscalls/table_*.go` are generated by `tools/gensyscalls` from the
  kernel syscall tables (x86_64 and arm64 numbers differ, the binary picks the
  table for the architecture it was built for).
- `bpf/headers` is vendored from the cilium/ebpf examples (profiler only). The
  shield and bypass programs use libbpf headers (`libbpf-dev`) and CO-RE, so
  no `vmlinux.h` is needed.
